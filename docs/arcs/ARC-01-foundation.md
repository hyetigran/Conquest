Superseding this arc's original plan (a nested `godot4/` subdirectory with an Arc 10 promotion step): the original Godot 3 project has already been relocated, unmodified, to `legacy/` (`legacy/Source/`, `legacy/Assets/`, `legacy/Images/`, `legacy/project.godot`, `legacy/icon.png`, `legacy/icon.png.import`, `legacy/default_env.tres`), preserving git history via `git mv`. `README.md`'s image links were updated to `legacy/Images/...` accordingly. `docs/RECON.md` and `docs/BUGS-MITIGATIONS.md` both carry a path note explaining that every file citation in the audit should be read with a `legacy/` prefix.

This is a cleaner outcome than the subdirectory plan: **the new Godot 4 project builds directly at the repo root from Slice 01-01 onward — no nested folder, no Arc 10 promotion/cutover step needed.** `legacy/` itself is the freeze; a `git tag godot3-original` is still cheap extra insurance but is no longer the primary safety mechanism.

## Stories & slices

### Story 1 — Scaffold Godot 4 at the repo root

- **Slice 01-01 — Tag and scaffold. ✅ Done.** `git tag godot3-original` at the commit where `legacy/` was created. Created a fresh root-level `project.godot` with settings ported from the audited original: `config/name="Conquest"`, viewport 1280×720 with `stretch/mode="canvas_items"` (Godot 4's default `stretch/aspect="keep"` matches the original and is correctly omitted from the saved file since it equals the default), the full input map (`left`/`right`/`up`/`down`/`previous`/`next`/`quit`/`move`/`reveal_country_names`), and pause-aware-picking/pixel-snap physics/rendering settings. No `legacy/Source/` code copied yet, no `[autoload]` section (empty/absent until `GamePlay`/`Server` are rebuilt).

  Input-map key events were generated by running a one-off `SceneTree` script (via `Godot --headless -s <script>`) that set each action using the engine's own `KEY_*` constants rather than hand-typing Godot 4's keycode integers — this sidesteps the Godot 3→4 keycode-encoding change entirely (Godot 3 used `SPKEY`-offset scancodes like `16777231` for Left; Godot 4 uses a different base offset, `4194319`) by asking the engine to resolve the correct value itself. The script was deleted after one run, matching Slice 01-02's converter-output pattern of not leaving one-off tooling behind.

  **Gate correction (a real plan-vs-reality mismatch, recorded per the slice-loop's reflection rule):** the originally planned gate, `Godot --headless --path . --quit`, does not work for a project with no main scene yet — Godot prints `Error: Can't run project: no main scene defined in the project.` and then **hangs indefinitely in headless mode instead of exiting**, because `--quit`'s "quit after first iteration" logic never triggers if the main-loop's initial run attempt fails this way. Confirmed by observing the process still alive in `ps` well past a 120s timeout. The corrected, actually-verified gate for any main-scene-less state: run a trivial `-s <script>` that extends `SceneTree` and calls `quit()` explicitly (exactly the technique already used for the input-map setup above) — confirmed exit code 0. Later arcs that still have no main scene (Arc 02, Arc 03) should use this same pattern, not bare `--quit`, until Arc 05 gives the project an actual main scene. **Effort:** 0.5–1 day (as estimated).
- **Slice 01-02 — Converter first pass, committed raw, kept out of the way. ✅ Done.** Copied `legacy/Source/`, `legacy/Assets/`, `legacy/project.godot`, `legacy/icon.png(.import)`, `legacy/default_env.tres` into a scratch working location outside the repo, ran `Godot --headless --convert-3to4` against that scratch copy once (219/219 files converted, 0 failures, 0.36s), then copied **only the converted `Source/` and `Assets/`** into the repo root — not the converter's own `project.godot` (Slice 01-01's hand-authored, engine-verified one stays authoritative), not its `.godot/` cache. `legacy/` was never touched; the conversion ran entirely on a disposable copy.

  Spot-checked a sample converted file (`InActiveState.gd`) against the audit: the converter correctly modernized *syntax* (Godot 3's `.enter(country)` super-call syntax became `super.enter(country)`) but, exactly as [MIGRATION-OPTIONS.md](../MIGRATION-OPTIONS.md) predicted for Route C-style tooling, **left F-001's shadowed-loop-variable crash bug fully intact** (`for country in GamePlay.bordering_countries[country.name]:` still shadows the method's own `country` parameter). This is the concrete, observed confirmation that converted-but-unreviewed code is a first draft, not a finished state — Arc 03 still needs to fix this file per the findings map, the converter bought only the mechanical syntax porting, not the bug fix.

  **Gate:** converter run completed without throwing (219/219, 0 failures). Root project reopened headless (via the same `-s <script>`-with-explicit-`quit()` pattern from Slice 01-01, since there's still no main scene) with `Source/`/`Assets/` now present at the root — exit 0, no fatal engine-level error. **Effort:** 0.5 day (as estimated).

### Story 2 — Test infrastructure (GUT)

- **Slice 01-03 — Install GUT. ✅ Done.** Network fetch turned out to work fine in this environment: shallow-cloned `bitwes/Gut` at tag `v9.7.1` (the Godot-4-targeted line — GUT's `v7.x` tags are for Godot 3) into scratch space, copied only `addons/gut/` into the repo (MIT-licensed, compatible with this project's license), and enabled it via `project.godot`'s `[editor_plugins] enabled=PackedStringArray("res://addons/gut/plugin.cfg")`.

  Getting the CLI runner (`addons/gut/gut_cmdln.gd`) to actually work required one extra step not in the original plan: GUT's classes aren't resolvable until Godot's asset/script import pass has run at least once, so `Godot --headless --path . --import` had to be run first (it errors clearly — `Some GUT class_names have not been imported` — telling you exactly what to do). That import pass turned out to double as a real verification of Slice 01-02's converted assets: all 219 `legacy/`-derived files re-imported cleanly under Godot 4 with no fatal errors, and it generated the expected new Godot 4 artifacts — one `.gd.uid` per script (Godot 4.3+'s UID-based script identity) and refreshed `.import` metadata for every asset. All committed as part of this slice, since they're a direct, mechanical consequence of the import pass this slice needed anyway.

  **Confirmed `legacy/` stayed untouched** by this import pass despite `--path .` covering the whole repo tree — `legacy/`'s own `project.godot` acts as a nested-project boundary that Godot's scanner doesn't descend into. Useful confirmation that the freeze holds even under whole-tree operations, not just ones that explicitly avoid the directory.

  **Gate:** stronger than originally planned — rather than just confirming `plugin.cfg` parses, ran GUT's actual CLI runner (`Godot --headless --path . -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit`), which correctly reported version `9.7.1` and a clean "path does not exist" error for the not-yet-created `res://tests` directory (expected — that's Slice 01-04's job) rather than any class-loading or plugin error. **Effort:** 0.5 day (as estimated; the fetch was not the blocker after all).
- **Slice 01-04 — First smoke test.** One trivial GUT test (e.g. asserting the root project's `ProjectSettings` has the expected `config/name`) run via `Godot --headless -s addons/gut/gut_cmdln.gd` with GUT's standard exit-code convention (0 = all pass). This is the test the rest of the migration's "merge gate" in [MIGRATION-GODOT4.md](../MIGRATION-GODOT4.md) depends on existing. **Gate:** the command above exits 0 locally. **Effort:** 0.5 day.

### Story 3 — Headless CI

- **Slice 01-05 — GitHub Actions workflow.** `.github/workflows/godot-tests.yml`: pulls a pinned Godot 4.7.1 Linux headless binary, runs the same GUT command as Slice 01-04 against the repo root, fails the check on nonzero exit. This becomes the gate every subsequent slice in every arc must pass before being presented for human review, per the slice-loop protocol. **Gate:** a deliberately-broken test in a scratch commit makes the workflow fail red; reverting makes it pass green (verifies the gate actually gates, not just that it runs). **Effort:** 0.5–1 day (CI YAML + one iteration to fix inevitable path/version mismatches).
