# Bugs & Mitigations — Conquest

> **Path note:** all locations below cite the pre-migration layout; the original Godot 3 project now lives under `legacy/` (see [RECON.md](./RECON.md)'s path note) — e.g. `Player.gd` is `legacy/Source/Gameplay/Player/Player.gd`.

> Synthesized from 40 per-file analyses (`docs/ui/`, `docs/gameplay/`, `docs/server/`, `docs/data/`) plus `docs/RECON.md`'s free findings. Every finding cites source. This catalog is the triage list for any remediation or rewrite.

## Top findings (plain language)

1. **A turn-transition crash bug that fires on essentially every match with an Attack phase.** `InActiveState.gd`'s check for "does this country have an attackable enemy neighbor" accidentally reuses the same variable name for two different things, so it ends up calling a property that only exists on game objects on a plain piece of text instead — which throws an error every time. (F-001)
2. **Online multiplayer likely spawns the wrong number of players.** A lobby-creation bug means the player roster the host sends to the server only ever has one entry, and the code that spawns player pieces for an online match uses that same roster's size to decide how many players to create — so a full lobby could start a match with only one player node. (F-002, F-004)
3. **Starting troop bonuses can silently disagree between players' screens in online play.** The dice-style random roll that decides how many bonus troops a player gets at the start of the game is never sent to other players — each computer rolls its own, different number, for the same player. (F-005)
4. **A player being eliminated never shows a notification in offline/local games**, and only shows up for other people's screens in online games, never the screen where the elimination actually happened. (F-006)
5. **An unrestricted "run this method on this game object" networking command** exists in the client, with no list of what's safe to call — its safety currently depends entirely on the separate server (not audited here) never forwarding untrusted data into it.
6. **Widespread copy-paste duplication**: two identical 42-country map-adjacency lists that must be edited in two places to stay correct, two nearly-identical menu-navigation scripts, three copies of the same troop-count pluralization logic, and five copies of the same "is it my turn" permission check (one of which is disabled).
7. **A fully-built but entirely disconnected "play on the same device" screen** — laid out, styled, and configured, but with zero button wiring and unreachable from any menu.

## Notes on findings that did not survive verification

- **RECON.md's original framing of the server-address default was corrected during the Server.gd read** (Phase 3): the shipped default is the production server, not localhost — see F-034 for the corrected, narrower finding.
- **Menu.gd's and HostGameMenu.gd's "no independent bounds check on player count" concerns** (flagged in Phase 2 as smells) were checked against the actual `.tscn` scene data in Phase 4: both `PlayersRange`/`lobby_players` controls are correctly configured `min_value=2, max_value=6` — the UI layer already enforces sane bounds, so no catalog row was created for this.
- **`PlayersQueue.gd`'s infinite-loop risk and `Country.gd`'s `_process`/`update()` guard asymmetry** were both downgraded from their initial pending-confirmation severity after the Phase 6 deep dive (see F-042 and F-007) — recorded with their revised severities above, not at their original higher guesses.
